# SortLab

Учебный проект на Java для сортировки автомобилей. Есть графический интерфейс на JavaFX, выбор алгоритма и поля сортировки, загрузка данных из файла и сохранение результата.

Алгоритмы сортировки написаны вручную. Для хранения автомобилей используется своя коллекция `CustomArrayList`.

## Что хранится в программе

Для проекта выбран класс `Car` — автомобиль с тремя полями:

- `model` — модель;
- `power` — мощность;
- `year` — год выпуска.

Автомобили создаются через Builder:

```java
Car car = new Car.Builder()
        .model("BMW M5")
        .power(600)
        .year(2020)
        .build();
```

Сначала задаются поля, потом `build()` проверяет их и создаёт объект.

Проверки такие:

- модель не должна быть пустой;
- мощность должна быть больше нуля;
- год должен быть от 1886 до 2100 включительно.

После создания поля автомобиля изменить нельзя.

## Как запустить

В текущем `pom.xml` указаны Java 27 и JavaFX 21.0.6. Для запуска через Maven нужны JDK 27 и установленный Maven.

Из папки проекта:

```bash
mvn clean javafx:run
```

Также можно открыть проект в IDE как Maven-проект и запустить цель `javafx:run`.

Основная точка входа — `SortLabApplication`. Класс `Main` пока только выводит приветствие в консоль и окно приложения не запускает.

## Как заполнить коллекцию

### Случайные автомобили

В поле «Количество» вводится число от 1 до 10 000, затем нажимается «Сгенерировать».

Генератор выбирает:

- модель из заранее заданного списка;
- мощность от 100 до 800;
- год от 1990 до 2026.

Новая генерация заменяет текущую коллекцию.

Заполнение сделано через Stream: создаётся поток случайных автомобилей, ограничивается нужным количеством, затем объекты добавляются в свою коллекцию.

### Загрузка из файла

Кнопка «Загрузить CSV» открывает выбор файла.

Формат данных:

```text
model;power;year
BMW M5;600;2020
Audi RS6;630;2023
Toyota Supra;340;2021
```

Разделитель — точка с запятой. Кодировка — UTF-8.

Заголовок необязателен. Если он есть, должен находиться в первой строке. Пустые строки пропускаются.

Для каждой записи проверяется количество полей, числовой формат мощности и года, затем выполняются проверки Builder.

Если найдена ошибка, загрузка прекращается. В сообщении указывается номер строки. Текущая коллекция заменяется только после успешного чтения всего файла.

Поле «Количество» при загрузке не используется — читаются все записи.

### Ручной ввод

Кнопка «Добавить автомобиль» по очереди запрашивает модель, мощность и год.

Введённые значения проверяются через `CarValidator`. Если всё правильно, автомобиль добавляется к текущей коллекции. Отмена диалога прекращает добавление.

Ещё есть класс `CarManualInput` для ввода через консоль. Он принимает нужное количество автомобилей и повторяет запрос при некорректных данных. К графическому интерфейсу этот класс не подключён.

## Сортировки

В программе три алгоритма.

### Bubble Sort — пузырьком

Сравниваются соседние элементы. Если они стоят в неправильном порядке, программа меняет их местами.

Проходы повторяются, пока коллекция не будет отсортирована. Если за проход не было перестановок, сортировка заканчивается раньше.

### Insertion Sort — вставками

Левая часть коллекции постепенно становится отсортированной.

Программа берёт следующий элемент, сдвигает более крупные элементы вправо и вставляет его на подходящее место.

### Selection Sort — выбором

Программа находит минимальный элемент в оставшейся части коллекции и ставит его на очередную позицию.

Затем повторяет это для следующей позиции.

Все три алгоритма простые, но на больших коллекциях могут работать долго: в худшем случае количество операций растёт примерно как квадрат числа элементов.

## По каким полям можно сортировать

В интерфейсе можно выбрать:

- мощность — от меньшей к большей;
- год выпуска — от более раннего к более позднему.

Правила сравнения находятся в `CarComparators`.

Компаратор только сравнивает два автомобиля. Само перемещение элементов выполняет выбранный алгоритм.

## Зачем здесь Strategy

У всех сортировок общий интерфейс `SortStrategy<T>` с методом `sort()`.

`BubbleSort`, `InsertionSort` и `SelectionSort` реализуют этот интерфейс. `SortingService` получает выбранную стратегию и запускает её.

Это позволяет менять алгоритм, не переписывая сервис. Для добавления ещё одной сортировки нужно создать реализацию интерфейса и добавить её выбор в приложение.

## Визуализация

Для коллекций до 50 автомобилей сортировка по мощности или году автоматически запускается с анимацией.

Для сортировки по модели и коллекций больше 50 элементов используется обычная сортировка без анимации.

Для анимации есть отдельные версии алгоритмов:

- `ObservableBubbleSort`;
- `ObservableInsertionSort`;
- `ObservableSelectionSort`.

Они выполняют сортировку и сообщают о сравнениях и изменениях элементов.

`SortVisualizationService` сохраняет эти шаги как кадры. `SortAnimationPlayer` воспроизводит их, а `SortingVisualizer` рисует столбцы.

В интерфейсе доступны:

- «Пауза» — приостановить анимацию;
- «Продолжить» — продолжить воспроизведение;
- «Сброс» — остановить анимацию и показать первый кадр.

Сброс не восстанавливает коллекцию после уже завершённой сортировки.

Ползунок задаёт задержку между кадрами в миллисекундах. Чем больше задержка, тем медленнее анимация.

Также показывается количество сравнений и изменений. Изменение не всегда означает обмен двух элементов: например, при сортировке вставками это может быть сдвиг.

## Своя коллекция

`CustomArrayList<T>` — коллекция на основе массива.

Начальная вместимость — 10 элементов. Когда место заканчивается, создаётся массив в два раза больше, а старые элементы переносятся в него.

Основные методы:

| Метод | Что делает |
|---|---|
| `add(element)` | Добавляет элемент в конец |
| `get(index)` | Возвращает элемент по индексу |
| `set(index, element)` | Заменяет элемент |
| `remove(index)` | Удаляет элемент и сдвигает остальные |
| `getSize()` | Возвращает количество элементов |
| `isEmpty()` | Проверяет, пуста ли коллекция |
| `clear()` | Удаляет все элементы |
| `iterator()` | Позволяет использовать `for-each` |
| `stream()` | Создаёт последовательный Stream |

При неправильном индексе выбрасывается исключение.

Коллекция не является потокобезопасной. Пока несколько потоков читают её при подсчёте, изменять её нельзя.

Для отображения в таблице используется стандартный `ObservableList`, но сами обычные сортировки работают с `CustomArrayList`.

## Сортировка только чётных значений

Дополнительный режим реализован в `EvenFieldSort`.

Он работает так:

1. Выбирает объекты с чётным значением числового поля.
2. Складывает их во временную коллекцию.
3. Сортирует выбранным алгоритмом.
4. Возвращает на позиции, где изначально стояли чётные элементы.

Объекты с нечётными значениями остаются на своих местах.

Например, для мощности:

```text
До:    600, 351, 340, 475, 520
После: 340, 351, 520, 475, 600
```

Использование:

```java
SortStrategy<Car> strategy = new EvenFieldSort<>(
        new BubbleSort<>(),
        Car::getPower
);

strategy.sort(cars, CarComparators.byPower());
```

Здесь `Car::getPower` определяет, какое поле проверяется на чётность. Компаратор задаёт порядок сортировки. Для выполнения условия задания они должны относиться к одному числовому полю.

Сейчас этот режим проверяется отдельными тестами. Кнопки или переключателя для него в интерфейсе пока нет.

## Сохранение в файл

Кнопка «Сохранить» записывает текущую коллекцию в текстовый файл через `CarFileWriter`.

Используется режим добавления: существующие данные не стираются, новый блок записывается в конец.

Каждый блок содержит описание, заголовок полей и автомобили.

Важно: сохраняется именно текущая коллекция. Программа не проверяет, была ли она предварительно отсортирована.

Выходной файл предназначен для просмотра результатов. Загрузить его обратно через `CarFileReader` без подготовки нельзя: перед CSV-заголовком записывается строка с описанием результата.

## Многопоточный подсчёт

`ParallelSearchService` считает элементы, которые подходят под переданное условие.

Методу `countMatches()` передаются:

- коллекция;
- условие проверки;
- количество потоков.

Коллекция делится на участки. Каждый поток считает совпадения в своей части, затем результаты складываются.

Пример подсчёта автомобилей мощностью 600:

```java
ParallelSearchService<Car> service = new ParallelSearchService<>();

long count = service.countMatches(
        cars,
        car -> car.getPower() == 600,
        4
);

System.out.println("Найдено: " + count);
```

Метод может выбросить `InterruptedException` или `ExecutionException`, поэтому вызывающий код должен их обработать или объявить через `throws`.

Для пустой коллекции возвращается 0. Количество потоков должно быть больше нуля. Если потоков запрошено больше, чем элементов, число рабочих потоков уменьшается.

Сейчас сервис используется в тестах. В графическом интерфейсе выбора условия и запуска подсчёта пока нет.

## Где что находится

Все пакеты ниже находятся внутри `ru.sortlab`.

| Пакет или класс | За что отвечает |
|---|---|
| `SortLabApplication` | Запуск JavaFX и загрузка окна |
| `controller` | Обработка кнопок и работа с интерфейсом |
| `model` | Автомобиль и Builder |
| `collection` | Своя коллекция |
| `comparator` | Сравнение автомобилей по полям |

| `generator` | Случайное заполнение |

Разметка окна находится в `main-view.fxml`, оформление — в `styles.css`.

## Тесты

Тесты написаны вручную, без JUnit. У каждого тестового класса есть `main()`, его можно запустить из IDE.

- `BubbleSortTest` — простая проверка пузырьковой сортировки.
- `SortingAlgorithmsTest` — три алгоритма по трём полям, всего девять проверок.
- `EvenFieldSortTest` — порядок чётных элементов и сохранение позиций нечётных для трёх алгоритмов.
- `CarGeneratorTest` — проверки генератора.
- `FileServiceTest` — чтение файла и добавление результатов без перезаписи.
- `ParallelSearchServiceTest` — подсчёт с разным количеством потоков, пустая коллекция и неправильное число потоков.

При неправильном результате тест выбрасывает `AssertionError`.

Файловый тест работает во временной папке и не изменяет файлы с данными проекта.

Эти тесты нужно запускать отдельно: в текущем `pom.xml` запуск их методов `main()` через `mvn test` не настроен.
